# Solver SDK

The TypeScript package is `@cow-silo/sdk`.

It provides these functions:

| Function | Result |
| --- | --- |
| `buildOrder` | Canonical Silo order data. |
| `encodeOrderPayload` | Raw ERC-1271 payload for `Silo.isValidSignature`. |
| `encodeSolverSignature` | CoW solver API signature with the Silo owner prefix. |
| `hashOrder` | CoW EIP-712 order digest from a Settlement domain separator. |
| `buildCommitInteraction` | Pre-interaction for `Silo.commit`. |
| `buildCommitInteractions` | Pre-interactions for several independent Silo orders. |
| `toSolverJitOrder` | Current CoW solver API JIT order object. |

The package uses `bigint` for token amounts. `buildOrder` requires the current `minimumBuyAmount` and rejects a lower limit. It remains a pure builder: it uses the supplied `sellAmount` and does not fetch balances, configuration, or prices. The solver controls those data sources.

## Funding adapter ABI

`siloAbi` includes `fundingAdapter()`, `setFundingAdapter(address)`, and `FUNDING_GAS_LIMIT()`. Funding starts disabled. Only the Silo owner can replace or disable the adapter.

`approvalFundingAdapterAbi` exposes `source()`, `silo()`, `availableBalance(token)`, and `fund(token)`. The source must approve the adapter as spender, not the Silo or Vault Relayer. Only the configured Silo can call `fund`.

For `ApprovalFundingAdapter`, set the order's `sellAmount` to the current Silo balance plus `availableBalance(sellToken)`. That view returns the smaller of the source balance and allowance to the adapter. Use zero expected funding when no adapter is configured. The shared `IFundingAdapter` interface requires only `fund(token)`; there is no mandatory quote method, amount argument, or arbitrary bytes input.

These reads are estimates for order construction. Inventory, allowances, and adapter configuration can change before execution. `commit` attempts funding with a fixed 200,000 gas cap, ignores failure and return data, then requires the actual Silo balance to match `sellAmount` exactly. The cap does not guarantee success for an undergassed outer transaction. A prefunded fallback must still match the supplied amount. Simulate the complete settlement, including commit. A standalone `verify` checks only the current balance and does not fund the Silo.
