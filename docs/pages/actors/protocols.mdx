# Protocols

## Why use Silo

Silo can convert many fee tokens into one treasury token. The planned production flow lets protocols use a shared, permissionless watchtower to post orders. A protocol can also run its own instance. CoW solvers compete to fill the orders through the standard auction flow.

## Proof-of-concept integration

The steps below apply to the current solver-created JIT implementation. The production watchtower and posted-order validation are planned work.

1. Select the resource token.
2. Select a treasury or deploy a Burner.
3. Select a non-zero minimum buy amount in the resource token.
4. Select a factory with the trusted Settlement.
5. Deploy a Silo through `SiloFactory`.
6. Send fee tokens to the Silo or configure optional adapter funding.
7. If testing surplus scoring for JIT orders, confirm that CoW Protocol recognizes the Silo as a surplus-capturing JIT owner.
8. Monitor settlements and received resource tokens.

Do not send the resource token to the Silo. The Silo cannot sell its resource token.

The appData document is fixed for each Silo/sell-token pair at the current hook gas limit. It tells solvers to execute the permissionless `prepare(sellToken)` pre-hook before signature validation. Use the SDK to get the exact document and hash for publication; the owner does not approve a generic appData hash.

## Optional source funding

A new Silo has no funding adapter. Direct transfers remain supported. To use approved source inventory, deploy `ApprovalFundingAdapter(source, silo)` with non-zero source and Silo addresses. Both addresses are immutable. The Silo owner then calls `setFundingAdapter(adapter)`. The source grants each sell-token allowance to the adapter, not to the Silo or Vault Relayer.

Only the fixed Silo can call the adapter's `fund(token)`. It transfers `min(source balance, source allowance to adapter)` into that Silo. Zero available inventory is a no-op. Source approval permits any account to trigger that transfer through `Silo.prepare(token)`, even if no order or trade follows. Do not use this approval when the source must retain the inventory until a completed sale.

The owner can replace the adapter or disable it with `setFundingAdapter(address(0))`. This does not revoke source allowances. Revoke the old adapter's allowances separately. A protocol-specific adapter must use the protocol's existing permissions; configuring an adapter does not grant a privileged withdrawal bypass.

Solvers must use the current Silo balance plus expected adapter funding as the sell amount. Changes to inventory, allowances, or adapter configuration can invalidate that amount. The Silo attempts funding with a fixed 200,000 gas cap and ignores failure. An adapter that needs more gas can fail; any fallback prefunded balance must still match the order amount exactly. An outer transaction revert also rolls back the source transfer.

## Hook gas limit

The owner can call `setHookGasLimit` to change the pre-hook gas limit from its default of 500,000. Zero is rejected. Choose a limit that covers preparation and optional funding, then simulate the complete settlement. A low limit can make the hook fail; a very large limit can exceed available transaction gas. The adapter's separate 200,000-gas cap does not change.

A limit update changes the expected appData hash for every sell token. Solvers must rebuild affected orders and publish the new exact documents. Restoring a previous limit can make its documents valid again, subject to the other order checks.

## Minimum buy amount

The Silo rejects orders whose `buyAmount` is below `minimumBuyAmount`. The value uses the resource token's smallest unit. For example, a USDC Silo can require a minimum USDC output, and a COW Silo can require a minimum COW output.

The minimum applies to each full-balance order. It is not a USD value unless the resource token is a USD-denominated token. It is also not a fair-price oracle. CoW solver competition determines execution value above the minimum.

The two-step owner can update the minimum. An update does not change the Silo address or its other order rules. Small balances remain in the Silo until a solver can meet the current minimum.
