# Deployers

## Before deployment

- Confirm the canonical CoW Settlement address.
- Confirm that the Settlement returns the expected Vault Relayer.
- Confirm Cancun EVM support on the target chain.
- Select the resource token and recipient.
- Select the initial buy amount and floor in the resource token's smallest unit. Check that your CoW driver accepts the [order expiry](/developers/sdk#build-a-jit-trade) for the chosen duration.
- Select the initial owner. The factory caller becomes the owner.
- Register the app data document and store its hash.
- Obtain the required CoW JIT owner configuration.

## Deploy

Use the Foundry scripts in `script/`. The scripts read `.env` values. They support simulation, broadcast, and verification.

Deploy the Burner before the Silo when the output must leave circulation. Set the Burner address as `RESOURCE_RECIPIENT`.

Set `INITIAL_BUY_AMOUNT` at or above `MINIMUM_BUY_AMOUNT`, which must be positive. Set `AUCTION_DURATION` in seconds. A descending auction needs a positive duration. Equal amounts give a fixed minimum and an effective duration of zero. Transfer ownership to the protocol through `transferOwnership`; the protocol must call `acceptOwnership`. Ownership controls the funding adapter. The auction settings are immutable.

Funding starts disabled. For optional source funding, deploy `ApprovalFundingAdapter(source, silo)` after the Silo, then have the Silo owner call `setFundingAdapter(adapter)`. The source must approve the adapter as the sell-token spender. Neither the Silo nor the Vault Relayer spends directly from the source. Record the adapter and source addresses with the deployment configuration.

Recompute CREATE2 predictions with the new Silo creation code. The same inputs and salt produce different addresses when the creation code changes. Existing deployed Silo instances remain unchanged; this feature does not upgrade them. Disabling or replacing an adapter does not revoke source allowances. Revoke old allowances separately.

## Record

Add verified addresses to `deployments/addresses.json`. Add the chain, factory, Silo, owner, Burner, Settlement, resource token, recipient, auction settings, app data, transaction hash, and source commit.

Do not label a deployment as official before an audit and the CoW integration review.
