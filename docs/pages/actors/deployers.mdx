# Deployers

Before deployment, confirm that the chain supports the Cancun EVM. Check the CoW Settlement address and the Vault Relayer returned by Settlement. Confirm the JIT owner configuration with CoW Protocol and check that the intended driver accepts the order lifetime for your chosen auction duration.

## Configure the Silo

Select the resource token and recipient. If the output must go to a Burner, deploy the Burner first and use its address as the recipient. Register the app data document and use its hash.

The factory caller becomes the owner. Call `createSilo(resourceToken, resourceRecipient, initialBuyAmount, minimumBuyAmount, auctionDuration, appData, userSalt)` on `SiloFactory`. The auction settings are immutable:

| Argument | Value |
| --- | --- |
| `initialBuyAmount` | Starting output for the full sell-token balance, in the resource token's smallest unit (`uint256`). Must be at least the floor. |
| `minimumBuyAmount` | Nonzero output floor in the same unit (`uint256`). |
| `auctionDuration` | Seconds for the required output to fall from the initial amount to the floor (`uint32`). Use a positive duration for a falling auction. |

If you use `script/DeploySilo.s.sol`, set `INITIAL_BUY_AMOUNT`, `MINIMUM_BUY_AMOUNT`, and `AUCTION_DURATION` to the corresponding integer values. For example, with a six-decimal resource token, `150000000`, `100000000`, and `7200` specify a drop from 150 to 100 tokens over two hours.

For a flat floor, set both amounts equal. The Silo then returns `0` from `auctionDuration()`, regardless of the duration supplied. A falling auction starts at deployment for every sell token. Later, a full sale restarts only the sold token's clock. Changing the auction settings requires a new Silo.

For CREATE2 prediction, call `predictSiloAddress` on the factory with the intended caller address followed by the same arguments as `createSilo`. For a flat auction, the factory uses zero for the duration in both calls. Use the factory for the Silo version you will deploy.

## Ownership and funding

Funding starts disabled. To enable source funding, deploy `ApprovalFundingAdapter(source, silo)` and have the owner call `setFundingAdapter(adapter)`. The source approves that adapter for each sell token. Replacing or disabling the adapter does not revoke those allowances. See [Protocols](/actors/protocols#optional-source-funding).

To transfer control of the adapter, call `transferOwnership` and have the new owner call `acceptOwnership`. Neither owner can change the auction settings.

## Record the deployment

Record the chain, contract addresses, owner, auction settings, app data hash, deployment transaction, and source commit. Include the source and adapter if funding is enabled. Verify the deployed addresses before adding them to `deployments/addresses.json`. Do not label a deployment as official before an audit and the CoW integration review.
