# Solvers

## Why use Silo liquidity

A Silo offers protocol-owned inventory. A solver can use this inventory to satisfy user demand in the same batch. The solver can also route the inventory through external liquidity.

Silo inventory has no onchain oracle price. Your solver must price the token and account for gas, transfer behavior, and execution risk.

## Discovery

Index `SiloCreated` and `MinimumBuyAmountSet` events. Store the immutable resource token, recipient, app data, Settlement address, and Vault Relayer. Read the current `minimumBuyAmount` before building an order. Read ERC-20 balances for tokens that your solver supports.

## Build a solution

1. Read the current Silo balance.
2. Read the current minimum buy amount and select an order limit at or above it.
3. Build a fill-or-kill sell order with the SDK.
4. Encode the ERC-1271 signature. The solver API signature starts with the 20-byte Silo address.
5. Add one `Silo.commit` pre-interaction for each Silo order.
6. Submit the JIT trade with `executedAmount` equal to the full sell amount.

```ts
import {
  buildCommitInteraction,
  buildOrder,
  toSolverJitOrder,
} from "@cow-silo/sdk";

const order = buildOrder({
  sellToken,
  resourceToken,
  resourceRecipient,
  sellAmount: balance,
  buyAmount: limitAmount,
  minimumBuyAmount,
  validTo: now + 300,
  appData,
});

const jitOrder = toSolverJitOrder(silo, order);
const preInteraction = buildCommitInteraction(silo, order, domainSeparator);
```

Use `buildCommitInteractions` when a settlement contains several Silo orders. Each order has an independent transient commitment.

The SDK emits the current CoW solver JIT wire format. Your solver still controls the solution graph and interaction placement. An order can execute above its limit; all executed resource-token output goes to the configured recipient.
