# Solvers

## Discover and quote inventory

Index `SiloCreated` from the factory and `FundingAdapterSet` from each Silo. Read the resource token, recipient, app data, and effective `auctionDuration()` from the Silo. Identify the sell tokens your solver can price. The Silo has no token registration step or price oracle.

For each candidate sell token, read its Silo balance and `currentMinimumBuyAmount(sellToken)` at the same block. The required output applies to that token's full balance. `minimumBuyAmount()` is the floor and can be lower than the current requirement. A full sale of this token can raise its required output before your order executes. Sales of other tokens cannot.

If `fundingAdapter()` is zero, use the Silo balance as `sellAmount`. For `ApprovalFundingAdapter`, add `availableBalance(sellToken)`, the smaller of the source balance and its allowance to the adapter. Other adapters need their own estimate; `IFundingAdapter` defines only `fund(token)`.

## Build and settle an order

Choose a buy amount at or above the current requirement. Build a fill-or-kill sell order with the [solver SDK](/developers/sdk). Use the chain's block timestamp to set a Silo execution deadline no more than 300 seconds ahead. Set the CoW order's `validTo` to that deadline **plus** the Silo's effective auction duration. Check that your driver accepts this wire lifetime before using it. The longer `validTo` preserves the fill record; it does not extend the Silo execution window.

Use `toSolverJitOrder(silo, order)` for the solver API. Its ERC-1271 signature starts with the 20-byte Silo address. Add `buildCommitInteraction(silo, order)` as a Settlement pre-interaction. It encodes `Silo.commit(order)` with the same order that the trade uses. Submit the JIT trade with `executedAmount` equal to `sellAmount`. No post-interaction is needed to restart the clock.

For several sell tokens in one Silo, use `buildCommitInteractions(silo, orders)`. Include at most one active order per Silo and sell token in the batch. A full fill restarts only that token's auction, even when another batch settles in the same block.

## Simulate the full settlement

Include the funding and commit pre-interaction in simulation. Standalone `verify(order)` checks the balance already in the Silo and does not call the adapter. During `commit`, the Silo attempts funding with a 200,000 gas cap and ignores call failure. The resulting balance must equal `sellAmount` exactly. Changes to balances or allowances can invalidate the order.

A commit without a trade can leave source inventory in the Silo, but does not restart the auction. If the settlement reverts, source transfers also revert. Refresh the balance, required output, and deadline before retrying a stale order.
